# Farmakon Q7 V3 — Visual Fidelity Lock / قفل الهوية البصرية المعتمدة

**القرار المعتمد:** 2026-11-01. **الأولوية:** هذا القيد يتقدم على أي اقتراح سابق لـ V3 يتضمن تغيير تصميم الواجهة أو ألوانها أو واجهة تسجيل الدخول.

## المطلوب الثابت
- الحفاظ على **تصميم تسجيل الدخول وإنشاء الحساب المعتمد** (التخطيط، الألوان، الهوية، توزيع العناصر، الخطوط، العلامة، أشكال البطاقات) وعدم استبداله بتصميم آخر.
- الحفاظ على الشكل والهوية الأصلية لواجهة الطالب الرئيسية (Dashboard) وتوسيع وظائفها وتحسين جودة استخدام العناصر الحالية **من دون فرض هوية أو طابع بصري جديد**.
- يُسمح بإصلاحات وصولية وأمنية وسلوكية وتحسين أداء وتنقل واستجابة وتكامل، بشرط ألا تغيّر العرض البصري الافتراضي أو تكسر المكونات الأصلية.
- لا استبدال للشعار أو تغيير درجات اللون أو إضافة طبقة CSS عامة قبل وجود مرجع بصري قابل للفحص وموافقة صريحة على تغييرات الشكل.
- أسلوب الأيقونات والأزرار يبقى متناسقاً مع الهوية المعتمدة، ولا يُستبدل بمكتبة أو طراز جديد لمجرد «التحديث».
- كل عنصر واجهة معروض يجب أن يقود إلى مسار حقيقي، أو يصف الخدمة غير المهيأة بصدق؛ دون محتوى مختلق.

## التصحيح المنفذ
- حُذف `src/app/v3.css` الذي فرض لوحة ألوان وشعار وتصميماً مختلفاً على الشاشات.
- أُزيل استيراد CSS من Root Layout.
- استُعيدت `src/components/platform/Icon.tsx` كما كانت في baseline دون رمز جديد.
- استُعيد تنظيم `Shell` الأساسي وعلامة F الأصلية، مع الاحتفاظ فقط بتفعيل المسار المحدد للمحاضرات/الكورسات وتحسين `aria-label` و`aria-pressed` و`type=button` في زر طي القائمة.
- لم يتغير `AuthForm` أو `StudentHome` أو أي ملف CSS مرئي أساسي عن baseline.
- أضيف اختبار مصدر ثابت لمنع تغيير ملفات الواجهة الرئيسية والدخول بصمت في GitHub Actions. أي تغيير بصري مقصود يتطلب مراجعته وتحديث الاختبار وشرح سببه.

## بوابة المعاينة
لا ترسل للمستخدم «مطابقة 100%» أو «تصميم نهائي» قبل توفر لقطة التصميم الأصلية ومقارنتها بلقطات فعلية من المنصة على 390 و1440 بكسل، العربية/الإنجليزية والفاتح/الداكن.
بناء Next.js ناجح أو HTTP 200 لا يثبتان الجودة البصرية. المعاينة تبقى Staging غير مرتبطة ببيانات حقيقية وغير جاهزة للإنتاج.
